## P1 — 버그

### P1-1. 개발 서버에서 데모 모드로 `/ai_supplement`에 들어가면 페이지가 계속 새로고침됨

**재현**
1. `fe-mock` 개발 서버에서 저장소를 비웁니다.
2. 테스트 모드로 로그인합니다.
3. `/ai_supplement`로 이동합니다.

**결과**
- 페이지가 0.1초 간격으로 계속 전체 새로고침됩니다. 서버 로그에 `GET /ai_supplement 200`이 끝없이 찍히고, `performance.navigation.type`이 `reload`입니다.
- `MSWProvider`가 준비되기 전에 다시 로드되므로 화면이 비어 있습니다.

**재현 범위**
- 개발 서버를 재시작해도, 저장소를 비워도, 모바일 에뮬레이션이 없는 탭에서도 똑같이 재현됩니다.

**재현되지 않는 경우**
- 같은 개발 서버에서 `fitcore_demo_mode`만 지우면(비데모) 정상입니다.
- 데모 상태라도 `/ai_quicklog`, `/`, `/my`, `/login`은 정상입니다.
- `next start` 운영 빌드에서는 데모 영양제가 정상 동작합니다.

**그 밖에 확인한 것**
- 2차 리뷰 때는 같은 개발 환경, 데모 상태에서 `/ai_supplement`가 정상이었습니다. 그래서 3차 변경(영양제 페이지의 `import("@/utils/demoAi")` 등) 이후에 생긴 회귀로 보입니다.
- 앱 코드에서 `location.reload`를 호출하는 곳은 없습니다. 다른 `next dev` 프로세스도 없었습니다.

**원인**: 찾지 못했습니다. 페이지 청크(`app_ai_supplement_page_tsx`)가 요청마다 200과 304로 번갈아 응답돼서, Turbopack HMR의 전체 새로고침이 의심됩니다.

**영향**: 로컬 개발 환경의 데모 시연에서 영양제 코치를 열 수 없습니다. 운영 배포에는 영향이 없습니다.

**기대**: 개발 서버의 데모 모드에서도 영양제 화면이 한 번만 로드돼야 합니다.

## P2 — 개선

### P2-1. "내 기록이 아니에요"를 눌렀거나 확인하지 않은 진행 중 운동을 확인 없이 이어서 할 수 있음
- 위치: `app/components/TodayWorkoutCard.tsx:199-209`. "아니에요"는 화면에서만 숨기고 저장소는 그대로 둡니다.
- `needsOverwriteConfirm`, 덮어쓰기 시트, 플레이어(`player/page.tsx`)는 소유권을 확인하지 않습니다.
- 재현(브라우저 확인)
  1. 소유자 없는 "옛 루틴" + A 로그인.
  2. 진행 중 카드에서 "내 기록이 아니에요".
  3. "다른 루틴 만들기" → "직접 만들기".
  4. "진행 중인 운동이 있어요" 시트가 뜨고, "이어서 하기"를 누르면 플레이어가 그 운동을 그대로 엽니다. `fitcore_workout_owner_unconfirmed`는 남은 채입니다.
- 그대로 끝내면 출처를 모르는 세트가 A 계정에 저장됩니다. 확인 단계가 막으려던 바로 그 경우입니다.
- 이전 버전 데이터에서 한 번만 생기는 경우라 P2로 봅니다.
- 기대: 다음 중 하나여야 합니다.
  - 소유권이 확인되지 않은 운동은 덮어쓰기 시트에서 "이어서 하기" 대신 확인 질문을 보이거나 바로 덮어씀.
  - 플레이어가 확인되지 않은 소유권이면 홈으로 보냄.
  - "아니에요"를 누르면 데이터를 지우거나 따로 옮김.

### P2-2. 로그아웃하면 그 화면이 반환 경로로 남아, 다음 로그인이 그 페이지로 들어감
- 재현(브라우저 확인): 데모에서 `/my` → "로그아웃" → A로 로그인 → 홈이 아니라 `/my`로 들어갑니다.
- 원인
  - `logout()`으로 토큰이 사라지면 `AuthProvider`가 보호 경로(`/my`)를 반환 경로로 기억합니다(`components/AuthProvider.tsx:66-70`).
  - `MyPageContent`의 `window.location.href = "/login"`이 그 뒤에 실행됩니다.
- 사용자가 직접 로그아웃했다면 반환 경로를 남기지 않아야 합니다. 그렇지 않으면 다른 계정으로 로그인해도 이전 사용자가 보던 화면으로 갑니다. 데이터는 계정별이라 노출은 없습니다.

### P2-3. 데모 퀵로그의 데모 안내가 7초짜리 토스트뿐임
- 위치: `app/ai_quicklog/page.tsx:224`.
- 검토 목록에는 데모 결과라는 표시가 남지 않습니다. 토스트를 놓치면 데모용 음식표 값을 실제 분석으로 오해할 수 있습니다.
- 영양제는 답변 본문에 "[데모 모드 예시 답변]"이 남는 것과 대비됩니다.
- 사소한 문구 문제입니다.

## 회귀 점검 (문제 없음)
- **set-aside 덮어쓰기 방지**: set-aside는 같은 소유자일 때만 합쳐집니다. 데모 → 로그아웃 → 데모 반복 시 `DEMO_OWNER_FLAG`로 데모 데이터가 A의 set-aside에 섞이지 않습니다. 탈퇴(`forgetAccountData`) 후 다른 계정이 로그인하면 set-aside는 소유자가 달라 버려집니다.
- **확인 질문 빈도**: 정상 소유 데이터(소유자 일치, `ownerSub` 일치)에는 확인 질문이 뜨지 않습니다. 새 기기의 첫 로그인처럼 루틴이 없으면 미확인 표시를 남기지 않습니다.
- **데모 플래그**: 개발 환경에서 플래그가 없으면 데모 로그인이 보이고, 운영에서는 숨겨집니다(`utils/demoLoginFlag.ts`). 관리자 권한은 `NEXT_PUBLIC_DEMO_ADMIN=true`일 때만 부여됩니다.
