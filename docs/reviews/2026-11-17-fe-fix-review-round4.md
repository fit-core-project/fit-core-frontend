## P1 — 버그

### P1-1. 개발 서버의 데모 모드에서 일부 화면을 직접 열면 계속 전체 새로고침됨 (3차 P1-1과 같은 증상, 다른 화면)

**재현**
1. `fe-mock` 개발 서버를 새로 띄우고 저장소와 서비스 워커를 비웁니다.
2. 테스트 모드로 로그인합니다.
3. 주소창으로 `/ai_routine/player`를 직접 엽니다(새로고침).

**결과**
- 서버 로그에 `GET /ai_routine/player 200`이 반복해서 찍힙니다.
- 몇 번 반복된 뒤 `MSWProvider`가 준비되지 않은 채 빈 화면에 멈추기도 합니다.

**재현 범위**
- 같은 세션에서 앞서 띄운 서버에서는 데모 상태의 홈(`/`)도 같은 증상을 보였습니다.

**재현되지 않는 경우**
- 같은 서버에서 `fitcore_demo_mode`만 지우면 플레이어 직접 진입이 정상입니다.
- 데모라도 홈에서 "이어서 하기"로 화면 이동하면 정상입니다.
- 데모 상태라도 `/terms`, `/ai_quicklog`, `/ai_supplement`(이번 수정 후)는 직접 열어도 정상입니다.
- 3차에서 운영 빌드(`next start`)의 데모는 정상이었습니다.

**회귀 여부**: 1차 리뷰 때 같은 개발 환경에서 데모 플레이어를 새로고침했을 때는 정상이었습니다.

**원인 분석**
- 영양제 화면에서 `demoAi.ts` import를 떼어 내자 그 화면은 고쳐졌습니다. 하지만 플레이어와 홈에서도 같은 일이 생기므로, 근본 원인은 그 모듈만이 아닌 것으로 보입니다.
- 공통점은 "개발 서버 + 데모 플래그 + 해당 화면을 전체 로드"입니다.
- 앱 코드에서 `location.reload`를 호출하는 곳은 없습니다. 재현 중에 소스 파일도 바뀌지 않았습니다.
- 조사할 곳: 데모일 때만 달라지는 전역 코드
  - `MainLayout`의 개발 전용 `LogViewer`(`token && isDemoMode()`일 때 렌더. 서버 렌더 결과와 달라짐)
  - 데모 분기가 있는 API 클라이언트를 import하는 페이지 모듈 그래프
  - Turbopack HMR

**영향**: 로컬 개발 환경에서 데모를 시연하다 새로고침하면 화면이 멈출 수 있습니다. 운영 배포에는 영향이 없습니다(3차 확인).

**기대**: 개발 서버의 데모 모드에서도 모든 화면이 한 번만 로드돼야 합니다.

## 참고 (건수에 넣지 않음)
- 플레이어 가드 토스트가 개발 환경에서 두 번 뜹니다. React StrictMode가 effect를 두 번 실행해서 생기는 개발 전용 현상입니다. 토스트에 `id`를 주면 사라집니다.
- 데모 퀵로그 Notice는 제목이 "데모 모드 예시 결과예요", 본문이 "데모 모드 예시 답변이에요…"입니다. 퀵로그에서는 "답변"보다 "결과"가 자연스럽습니다(`DEMO_AI_NOTICE` 공유 문구).

## 회귀 점검 (문제 없음)
- **수동 로그아웃 표시**: 보호 경로에서 토큰이 사라질 때 한 번만 사용되고 지워집니다. 브라우저에서 표시가 남지 않음을 확인했습니다. 만료(401) 경로는 이 표시를 쓰지 않아 반환 경로가 유지됩니다.
- **플레이어 가드**
  - 소유자 표시가 있고 소유권이 "unconfirmed"일 때만 동작합니다.
  - 로그인 상태에서는 소유자 표시가 항상 있으므로, 데모(소유자 = 데모)와 일반 소유 데이터는 통과합니다.
- **데모 모듈 분리**: `demoAi.ts`가 `demoSupplementAnswer`와 `DEMO_AI_NOTICE`를 다시 내보내므로 기존 import도 동작합니다. 퀵로그 파서는 그대로입니다.
