## P1 — 버그

### P1-1. 오프라인 배너가 헤더 뒤에 가려지고, 헤더가 없는 화면에서는 상단 버튼을 막음

**재현**: `navigator.onLine=false`로 바꾸고 `offline` 이벤트를 보냅니다(DevTools 오프라인과 같은 경로).

**헤더가 있는 화면(`/`, `/workout`, `/nutrition`, `/my`)**
- 배너(`fixed top-0 z-50`, y 8–72px)와 헤더(`relative z-50`, y 0–56px)의 z-index가 같습니다. DOM에서 뒤에 오는 헤더가 배너 위에 그려집니다.
- 그래서 배너의 문구 부분(y≈28, 40)은 `elementFromPoint`로 확인하면 **헤더**입니다.
- 화면에는 헤더 아래로 분홍 테두리 8px만 보이고, "인터넷 연결이 끊겼어요" 문구는 보이지 않습니다.

**헤더가 없는 전체 화면(플레이어, 퀵로그, 영양제 등)**
- 배너의 `<p>`에 `pointer-events-auto`가 있어서 y 8–72px 안의 상단 버튼을 덮습니다.
- 확인 결과
  - `/ai_quicklog`의 "영양 화면으로 돌아가기"가 막힙니다.
  - `/ai_routine/player`의 **"운동 나가기"와 "운동 종료"**도 막힙니다(`elementFromPoint`가 배너를 가리킴).
- 헬스장처럼 연결이 자주 끊기는 곳에서 운동을 일찍 끝내거나 플레이어를 나갈 수 없습니다. 모든 세트를 끝내야만 종료 화면으로 갈 수 있습니다.

**기대**
- 배너가 헤더 위에 보여야 합니다. z-index를 올리거나, 헤더 안이나 아래에 배치합니다.
- 전체 화면에서 상단 조작부를 막지 않아야 합니다. `pointer-events-none`을 유지하거나, 배너만큼 내용을 아래로 밀거나, 하단에 둡니다.

## P2 — 개선

### P2-1. 세션 메모 칸이 바로 저장되는 강도 버튼 아래에 있음
- 종료 화면은 "오늘 강도는 어땠나요?"(누르면 바로 저장되는 버튼 3개) → "메모(선택)" 순서입니다.
- 위에서부터 차례로 누르는 사용자는 메모 칸을 보기 전에 저장이 끝나고 요약 화면으로 넘어갑니다.
- 기대: 메모 칸을 강도 선택 위에 두거나, 강도를 고른 뒤 "저장" 버튼으로 확정합니다.

### P2-2. 공개 API 골든 예시에 `sessionNote`가 빠져 있음
- `docs/ops/golden-examples/workout-save.request.golden.json`에 새 선택 필드 `sessionNote`가 없습니다. 응답 골든에는 원래부터 있습니다.
- AGENTS.md는 공유 스키마가 바뀌면 골든 예시와 mock을 함께 갱신하라고 합니다. 선택 필드라 깨지는 것은 없지만 기준 문서가 실제 계약과 다릅니다.

## 참고 (건수에 넣지 않음)
- **mock 개발 환경의 뒤로 가기**: 뒤로 가기(`back_forward`)로 전체 로드되는 페이지가 빈 화면으로 멈추는 일이 다시 있었습니다. 새로고침하면 정상입니다.
  - 5차 참고와 같은 `MSWProvider`(시간 제한·`catch` 없음) 증상입니다.
  - mock 모드 개발 환경에서만 생기고, 이번 변경과는 무관합니다.
- **lbs 추정 1RM 표시**: kg으로 반올림한 값을 lb로 다시 바꿔서 0.1lb 차이가 날 수 있습니다(195.47 → 195.6). 표시 차이일 뿐입니다.
- **데모 플레이어의 지난 기록**: 데모 플레이어에는 "지난번 기록" 힌트가 나오지 않습니다. `recentRecordCache`가 데모에서 의도적으로 건너뜁니다. 데모 PR처럼 데모 이력에서 계산하면 시연할 때 더 자연스럽습니다.
- **빈 메모 저장값**: 데모는 빈 메모를 `""`로, BE는 null로 저장합니다. 화면에는 영향이 없습니다.
